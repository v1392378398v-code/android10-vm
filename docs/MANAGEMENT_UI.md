# 管理页、启动动画与运行诊断

当前交付目标：`0.2.88-miui12-android9-aosp-ime`，versionCode 98。

管理页使用原生 Android View，突出桌面启动入口，按应用与文件、设备连接、检查与管理
分组。`ManagementDashboard` 负责布局、状态展示和短动画，`MainActivity` 继续负责
操作、权限与页面跳转。入场和按压动画为有限时长，系统关闭动画时遵循系统设置。

启动 Android 10 时显示独立启动画面：小型环绕动画、黑底绿字终端、实际等待秒数
及“查看详细记录”。真实的校验计数、数据准备、ART、GPU、服务进程创建与就绪事件
逐行向上滚动；等待服务时每三秒记录一次实际等待状态。
画面退到后台或被日志对话框覆盖时停止动画和定时刷新，回到前台后按真实经过时间
恢复。桌面就绪后沿用现有自动进入全屏流程。
查看日志期间保持对话框，关闭后再自动进入已就绪的桌面。

`StartupLog` 负责阶段事件及私有目录持久记录，运行流程直接写入；内存快照最多
96 行，由既有状态通道发送。`BootTerminalView` 只负责绘制和滚动，显示与待播队列
分别上限为 64 和 48 行，不读取磁盘或执行启动任务。新启动生成独立会话标识并
清空旧事件，重建界面按本轮真实经过时间恢复。系统关闭动画时直接刷新日志。

面向用户的进度通过 `BootLogText` 展示为中文，例如“正在检查系统文件：256/2631”、
“正在启动相机功能”“正在等待桌面和应用准备完成”。原始事件保留在详细记录中，
显示文案不影响启动判断。首页使用“开启麦克风”“设置手机 Wi-Fi”“检查运行环境”
等操作说明；全屏等待提示为“正在显示桌面，请稍候…”。

原日志请求与启动共用同一个工作队列，启动繁忙时会一直排队；异步任务还直接引用
会被系统回收的 `Message`，回复目标可能丢失。当前实现固定回复目标，使用独立
诊断队列，展示设备与版本、当前状态、最近操作、各启动阶段及最近两个应用日志。
最近状态持久保存在应用私有目录，启动失败后也能读取。

`RuntimeDiagnostics` 每个文件最多读取末尾 6 KiB，使用文件定位读取，避免整体载入
大型日志。最近状态只保留简短原因；完整的近期阶段记录分别展示。对话框支持选字
和复制，日志文本由用户自行选择分享。

本地回归覆盖无活动会话时的失败日志、1 MiB 文件的有界读取和 UTF-8 内容。
v0.2.86 实机启动期间读取诊断约 2.56 秒，桌面及输入就绪约 22.21 秒。
v0.2.88 继续保留该界面；最新完整包验收见 [验证记录](VALIDATION.md)。
联想设备排查按用户要求暂停。

“导入应用到 Android 10”提供手机已安装应用列表和 APK 文件选择两个入口。
`InstalledAppsDialog` 负责后台读取、中文排序、搜索、图标及多选；`GuestApkImport`
负责复制安装包与逐项结果；客体 `GuestInstall` 使用同一安装会话提交 base 和 splits。
配置变更或关闭窗口时停止列表加载，应用复制及安装由已有服务工作队列执行。

`SystemUi` 集中处理 Android 9/10 的窗口边距和沉浸式全屏，较新系统使用对应公开 API。
